   103→
   104→Work Log:
   105→- Reproduced the bug with Agent Browser: scrolled through the pinned Expertise section measuring translateX + visible card indices at each step
   106→- Diagnosis: the transform used string percentages `useTransform(scrollYProgress, [0,1], ["1%", "-68%"])`. Framer Motion interprets "-68%" as -68% of the element's OWN width. The motion.div's own width = viewport width (1440px) because it is a flex child of a full-width sticky column — NOT the full track content width (~3256px). So the transform capped at -68% × 1440 = -979px, only revealing ~4 cards. Cards 5, 6 and the end card never entered view. The track appeared "stuck" short of its destination.
   107→- Measured values confirmed: translateX went 4 → -196 → -397 → -597 → -798 → -979 (capped), visible cards maxed at [3,4,5,6], end card never visible.
   108→- Root cause: percentage-based transforms on a flex container resolve against the container's own (viewport-constrained) width, not its overflowing content width.
   109→
   110→Fix (src/components/site/horizontal-expertise.tsx):
   111→- Added a `distance` state + a `useEffect` that measures `track.scrollWidth - window.innerWidth` on mount, on resize, and after a 300ms settle (fonts/layout). This is the exact px the track must travel.

This gives a 1:1 vertical-to-horizontal ratio so the scroll pace is comfortable and there is exactly enough pinned scroll distance to traverse the whole track (no overshoot, no undershoot). Previously the fixed `h-[320vh]` was both wrong-sized and paired with the wrong transform.

   246→    const prefersReducedMotion = { current: null };          // module-level mutable
   247→    function initPrefersReducedMotion() {

   249→        const mq = window.matchMedia("(prefers-reduced-motion)");
   250→        prefersReducedMotion.current = mq.matches;            // client: true/false immediately
   251→    }
   252→    function useReducedMotion() {
   253→        !hasReducedMotionListener.current && initPrefersReducedMotion();

   255→        return shouldReduceMotion;                            // SSR: null, client: true|false
   256→    }
